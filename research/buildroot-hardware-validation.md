# Buildroot hardware validation

Date: 2026-10-25. The owner booted the Buildroot SD image on the Mimic Pro
and confirmed that the LCD shell and USB keyboard work. A subsequent SSH
session from the Mac authenticated as root with a public key and collected
the read-only observations below.

| Component | Observation |
| --- | --- |
| Userspace | Buildroot 2025.02.19, ARM hard-float musl image |
| Kernel | Original Pearl `4.1.13-cl-som-am57x-ti-3.0` |
| Root filesystem | SD ext4 mounted read-write as `/dev/root` |
| USB input | `usbhid` loaded; keyboard confirmed by owner |
| Wi-Fi | ZT9101 module and `cfg80211` loaded; `wlan0` up at `192.168.31.215/24` |
| SSH | Dropbear accepted key authentication on port 22 |
| Original SSD | `sda1`–`sda4` mounted under `/mnt/pearl/` as ext4 `ro,norecovery` |
| Hardware devices | `/dev/ads7953.0`, `/dev/ads7953.1`, `/dev/mcasp.0`, `/dev/regulators` present |
| Bluetooth | `bluetoothd` running; no adapter has been tested |

The verified SD image is generated by `scripts/build_buildroot.sh`; its
Buildroot configuration is in `platform/buildroot/configs/open_mimic_defconfig`.
The SD ext4 partition matched the generated filesystem byte-for-byte after
flashing, and the FAT partition passed `diskutil verifyVolume`.

The IP address is a DHCP observation, not a fixed device address. Kernel
modules for additional USB adapters still need individual hardware tests.

The owner confirmed that the direct LCD shell starts cleanly without a login
prompt. A late `EDID block is all zeroes` kernel warning had overwritten the
prompt; limiting console printk output fixed the display while retaining the
warning in `dmesg`. An SSH login also confirmed that the new prompt follows
the working directory (`/root #`, `/tmp #`, `/ #`).
